# ``SymbolPicker/SPCategory``

A generic container that groups assets of a specific type under a named category for organized display in the SymbolPicker.

## Overview

The `SPCategory` struct is a vital data model used to organize ``SymbolPicker/SPDataAsset`` types (like SF Symbols or Emojis) into logical groups. This organization is key to providing a user-friendly interface where users can browse assets by their functional or thematic categories (e.g., "Nature", "Objects", "Weather").

### Generic Nature

`SPCategory` is generic over its ``SymbolPicker/SPCategory/elements``, which must conform to ``SymbolPicker/SPDataAsset``. This allows the same structure to be used for:
- Symbols (``SPSymbol``)
- Emojis (``SPEmoji``)
- Any other custom data asset types.

### Creation and Usage

Categories are typically generated by the ``SymbolPicker/SPDataManager`` during the fetching or searching process. The manager takes a flat list of assets and groups them based on their intrinsic category names.

Once created, arrays of `SPCategory` are passed to UI components like ``SymbolPicker/SPOptionList`` to be rendered as sections in a grid or list view.

### Standard Conformances

To ensure compatibility with SwiftUI and collection handling, `SPCategory` conforms to:
- **Identifiable**: Uses the category name as its unique ``SymbolPicker/SPCategory/id``.
- **Equatable**: Allows for efficient UI updates by comparing category names and their elements.
- **Comparable**: Enables alphabetical sorting of categories.
- **Sendable**: Ensures safety during asynchronous data loading operations.
